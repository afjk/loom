# Loom 仕様書

## 1. 概要

Loom は、ブラウザで動く**ステートレスなデータフロー実行エンジン**です。JSON でグラフを定義し、毎フレーム値を計算・更新します。

**英語での一行説明：**
> A stateless dataflow engine for the browser. Build reactive visual, audio, and 3D content by composing pure functions.

**日本語での説明：**

ブラウザで動くステートレスなデータフロー実行エンジン。純粋な関数の合成により、リアクティブな視覚・音響・3D コンテンツを構築します。

Loom の核は、以下の仕組みです：

1. グラフ状に配置された複数の「ノード」を定義（JSON で記述）
2. ノードどうしを「エッジ」で接続（値の流れを表現）
3. エンジンが毎フレーム、グラフを評価し、各ノードの出力値を計算
4. 外部から `engine.getValue()` で任意のノードの出力値を取得し、画面や音響に反映

## 2. 設計原則

### 原則 1：ステートレスを基本とする

状態（過去を引きずる値）を持たず、現在時刻と入力だけから出力が決まる純粋なデータフローを基盤とします。

**意図：**
- 任意のタイミングで同じ計算を再実行しても、同じ結果が得られる
- 記録と再生が容易
- マルチプレイの同期が単純

### 原則 2：状態が必要な部分は明示的に局在化する

「状態部品」という限定された種類の部品にだけ状態を持たせ、グラフ上で目に見える形で管理します。

**意図：**
- 状態を持つ部品がどこかは常に明確
- デバッグやテストが容易
- 状態管理の責任が明確に分離される

### 原則 3：副作用を出口側に集める

外部への副作用（位置や色を変える、音を鳴らす、メッセージを送るなど）は「シンク」専用部品でのみ行います。中間の計算は副作用を持ちません。

**意図：**
- 中間の計算ロジックが純粋で、テスト・再利用が容易
- 副作用がどこで起きるかが明確
- グラフの再利用性が高い

### 原則 4：テキスト表現とビジュアル表現の二重持ち

内部はテキストの専用記法（DSL）で持ち、UI はそれを視覚化します。両方向に変換可能で、人間も AI も自由に行き来できます。

**注意：** 第ゼロ段階では DSL とビジュアル UI は実装せず、JSON 直書きから始めます。

**意図：**
- テキスト形式により、バージョン管理・AI 処理が容易
- ビジュアル UI により、直感的な編集が可能
- 両者の変換が可能なため、ツール化が容易

## 3. データフローモデル

### 3.1 値の二種類

すべての値は次のどちらかに分類されます。

**連続値（Behavior）**

常に何らかの値が流れている「川」のようなもの。時間的に途切れません。例：

- 時計（経過時間）
- Sin 波（周期的な振動）
- 温度センサーの現在値
- マウスのポインタ位置

第ゼロ段階では、連続値のみを扱います。

**イベント（Event）**

時々瞬間的に発生する「雷」のようなもの。時間的に離散的です。例：

- クリック
- キープレス
- メッセージ受信
- 閾値超え（値が特定の値を越えたとき）

イベントは第一段階以降で導入します。

### 3.2 ノード（部品）の 5 カテゴリ

部品は次の 5 つのカテゴリに分かれます。

#### ソース部品

入力なしで値を生み出すノード。

**例：** `clock`（時刻）、`constant`（定数）

#### 入力部品

外界から値を受け取るノード。ユーザーの操作やネットワーク通信などが対象。

**例：** `pointerPosition`（マウス位置）、`pointerClick`（クリック）、`webhook`（HTTP リクエスト）

第ゼロ段階では実装されません。

#### 変換部品

純粋な計算で値を変換する。状態を持ちません。

**例：** `add`（足し算）、`multiply`（掛け算）、`sine`（正弦波）、`map`（配列変換）

#### 状態部品

内部に状態を持つ唯一のカテゴリ。過去の値を記憶し、それに基づいて出力を決定します。

**例：** `accum`（積分）、`smooth`（なめらか化）、`delay`（遅延）

第ゼロ段階では実装されません。

#### シンク部品

外部への副作用を持つノード。値を受け取り、画面・音響・ネットワークなどに影響を与えます。

**例：** `setPosition`（位置変更）、`playSound`（音声再生）、`broadcastEvent`（イベント送信）

第ゼロ段階では実装されません。

## 4. 第ゼロ段階のスコープ

### 実装対象

- ✅ 評価器の中核（JSON グラフを受け取り、毎フレーム値を計算する）
- ✅ ノード 5 種類のみ：`clock`、`constant`、`sine`、`add`、`multiply`
- ✅ ブラウザ環境のみ（Node.js 対応は第一段階以降）
- ✅ 単一クライアント（ネットワーク同期なし）
- ✅ JSON でグラフ定義、`engine.getValue()` で外部から値を取得
- ✅ ESM 形式の単一ファイル（`loom.js`）として配布
- ✅ 依存ライブラリゼロ（Three.js などへの依存も持たない）

### 実装外（第一段階以降）

- ❌ テキスト記法（DSL）とそのパーサ
- ❌ ビジュアルノードエディタ
- ❌ イベント型のノード
- ❌ 状態を持つノード（`accum`、`smooth` など）
- ❌ シンクノード（`setPosition` など）
- ❌ マルチプレイ・broadcast 機能
- ❌ AI 連携用ツール定義
- ❌ Three.js / SceneSync 連携アダプタ
- ❌ npm パッケージング

## 5. ノード仕様（第ゼロ段階の 5 種類）

### ノード型のメタデータ構造

Loom の各ノード型は、内部的に以下の構造を持つ **メタデータオブジェクト** として定義されます。

```javascript
{
  category: "source" | "transform" | "input" | "state" | "sink",
  inputs: {
    <portName>: { type: "number", default: <value> }
  },
  outputs: {
    <portName>: { type: "number" }
  },
  params: {
    <paramName>: { type: "number", default: <value> }
  },
  evaluate: ({ inputs, params, ctx }) => ({ <outputs> })
}
```

各フィールドの意味：

- `category`：ノードのカテゴリ（ソース、変換、入力、状態、シンクのいずれか）
- `inputs`：入力ポートの定義。各ポートは型とデフォルト値を持つ
- `outputs`：出力ポートの定義。各ポートは型を持つ
- `params`：パラメータの定義。各パラメータは型とデフォルト値を持つ
- `evaluate`：評価関数。`inputs`（接続済みの入力値）、`params`（パラメータ値）、`ctx`（評価コンテキスト）を受け取り、出力値を返す

この構造により、以下が実現されます：

- グラフ検証（型チェック、ポート存在確認）
- エラーメッセージの自動生成
- 第一段階以降での UI 自動生成、ドキュメント生成、AI 用スキーマ生成

第ゼロ段階のノード型は、すべてこの構造に従って定義されます。仕様書の以下のノード説明は、このメタデータ構造を人間向けに記述したものです。

### 入力・パラメータの統一ルール

Loom のすべてのノードは、以下のルールに従って入力値を解決します。

1. **入力ポートにエッジが接続されていれば、その値を使う**
2. **未接続なら、`params` の同名キーの値を使う**
3. **`params` にも値がなければ、ノード型のデフォルト値を使う**

このルールにより、`params` は「動的に変えたい入力のデフォルト値」として機能します。実行中にあるパラメータを動的に制御したくなったら、対応する入力ポートにエッジを繋ぐだけで済みます。

例：

```json
{
  "id": "wave",
  "type": "sine",
  "params": { "freq": 1.0, "amplitude": 0.5 }
}
```

このとき、

- `wave.freq` ポートが未接続なら、`params.freq`（=1.0）が使われる
- `wave.freq` ポートにエッジが接続されていれば、その値が使われる（`params.freq` は無視）

これにより、`pointer.x → sine.freq` のような動的制御が、グラフ構造を変えずに可能になります。

### 5.1 clock

**カテゴリ：** ソース部品

**入力：** なし

**出力：**
- `t`（経過秒、エンジン起動時を 0 とする）
  - 型：`number`（double）

**パラメータ：** なし

**説明：**

エンジン起動からの経過時間（秒）を常に出力します。

**例：**
```json
{
  "id": "timer",
  "type": "clock"
}
```

### 5.2 constant

**カテゴリ：** ソース部品

**入力：** なし

**出力：**
- `out`（定数値）
  - 型：`number`（デフォルト 0）

**パラメータ：**
- `value`（出力する定数値、型：`number`、デフォルト 0）

**説明：**

パラメータで指定した定数値を常に出力します。変わりません。

**例：**
```json
{
  "id": "freq_source",
  "type": "constant",
  "params": {
    "value": 2.5
  }
}
```

### 5.3 sine

**カテゴリ：** 変換部品

**入力：**
- `t`（時刻、必須）
  - 型：`number`
  - 未接続時は `0` を使用
- `freq`（周波数、Hz、オプショナル）
  - 型：`number`
  - 未接続時は `params.freq`（デフォルト 1）を使用
- `amplitude`（振幅、オプショナル）
  - 型：`number`
  - 未接続時は `params.amplitude`（デフォルト 1）を使用
- `phase`（位相、ラジアン、オプショナル）
  - 型：`number`
  - 未接続時は `params.phase`（デフォルト 0）を使用
- `offset`（オフセット、オプショナル）
  - 型：`number`
  - 未接続時は `params.offset`（デフォルト 0）を使用

**出力：**
- `out`（正弦波出力）
  - 型：`number`
  - 計算式：`sin(t * freq * 2π + phase) * amplitude + offset`

**パラメータ：**
- `freq`（周波数、Hz、型：`number`、デフォルト 1）
- `amplitude`（振幅、型：`number`、デフォルト 1）
- `phase`（位相、ラジアン、型：`number`、デフォルト 0）
- `offset`（オフセット、型：`number`、デフォルト 0）

**説明：**

時刻 `t` を入力として、正弦波を計算します。周波数、振幅、位相、オフセットでカスタマイズ可能です。

**例：**
```json
{
  "id": "oscillator",
  "type": "sine",
  "params": {
    "freq": 2.0,
    "amplitude": 1.5,
    "phase": 0,
    "offset": 0
  }
}
```

### 5.4 add

**カテゴリ：** 変換部品

**入力：**
- `a`（加数、必須）
  - 型：`number`
  - 未接続時は `0` を使用
- `b`（加数、オプショナル）
  - 型：`number`
  - 未接続時は `params.b`（デフォルト 0）を使用

**出力：**
- `out`（合計）
  - 型：`number`
  - 計算式：`a + b`

**パラメータ：**
- `b`（入力 `b` が未接続のときのデフォルト値、型：`number`、デフォルト 0）

**説明：**

2 つの数値を足し合わせます。入力 `b` が未接続の場合、`params.b` の値が使われます。

**例：**
```json
{
  "id": "summer",
  "type": "add",
  "params": {
    "b": 5
  }
}
```

### 5.5 multiply

**カテゴリ：** 変換部品

**入力：**
- `a`（被乗数、必須）
  - 型：`number`
  - 未接続時は `1` を使用
- `b`（乗数、オプショナル）
  - 型：`number`
  - 未接続時は `params.b`（デフォルト 1）を使用

**出力：**
- `out`（積）
  - 型：`number`
  - 計算式：`a * b`

**パラメータ：**
- `b`（入力 `b` が未接続のときのデフォルト値、型：`number`、デフォルト 1）

**説明：**

2 つの数値を掛け合わせます。入力 `b` が未接続の場合、`params.b` の値が使われます。

**例：**
```json
{
  "id": "scaler",
  "type": "multiply",
  "params": {
    "b": 0.5
  }
}
```

## 6. グラフ定義の JSON フォーマット

### 基本構造

グラフは、以下のフィールドを持つオブジェクトで表現されます。

```json
{
  "loom": "0.0.1",
  "meta": { ... },
  "nodes": [ ... ],
  "edges": [ ... ]
}
```

- `loom`（オプショナル、文字列）：グラフの記述に使われた Loom 仕様のバージョン。将来のマイグレーションに備えて記述を推奨します。第ゼロ段階では `"0.0.1"` を指定。
- `meta`（オプショナル、オブジェクト）：グラフのメタ情報。`name`（文字列）、`description`（文字列）、`author`（文字列）など、自由なフィールドを持つことができます。エンジンは `meta` の中身を解釈しません。
- `nodes`（必須、配列）：ノードの定義
- `edges`（必須、配列）：エッジの定義

`loom` と `meta` フィールドは、第ゼロ段階のエンジンには無視されますが、将来のバージョン管理や AI による生成・解釈のために、記述を推奨します。

例（メタ情報付き）：

```json
{
  "loom": "0.0.1",
  "meta": {
    "name": "Simple Sine Wave",
    "description": "A sine wave driven by clock",
    "author": "afjk"
  },
  "nodes": [...],
  "edges": [...]
}
```

### nodes 配列

各ノードは以下の構造を持ちます：

```json
{
  "id": "unique_node_id",
  "type": "node_type_name",
  "params": { ... }
}
```

- `id`（必須）：ノードを一意に識別する文字列。グラフ内で重複してはいけません。
- `type`（必須）：ノードの型（`"clock"`、`"constant"`、`"sine"`、`"add"`、`"multiply"` など）
- `params`（オプション）：ノードのパラメータ。型によって異なります。省略可能で、その場合はデフォルト値が使われます。

### edges 配列

各エッジは、値の流れを表現します：

```json
{
  "from": "sourceNodeId.portName",
  "to": "targetNodeId.portName"
}
```

- `from`（必須）：送信側のノードの出力ポート（`"nodeId.outputPortName"` 形式）
- `to`（必須）：受信側のノードの入力ポート（`"nodeId.inputPortName"` 形式）

### 例：Sin 波の値を取り出すグラフ

時刻を取得し、その時刻に対する正弦波を計算するグラフです：

```json
{
  "nodes": [
    {
      "id": "timer",
      "type": "clock"
    },
    {
      "id": "wave",
      "type": "sine",
      "params": {
        "freq": 1.0,
        "amplitude": 1.0,
        "phase": 0,
        "offset": 0
      }
    }
  ],
  "edges": [
    {
      "from": "timer.t",
      "to": "wave.t"
    }
  ]
}
```

このグラフでは：
1. `clock` ノードが時刻 `t` を生成
2. その時刻が `sine` ノードに入力
3. `sine` ノードが正弦波 `out` を出力

外部から `engine.getValue("wave.out")` を呼ぶと、現在の正弦波の値が得られます。

### 別の例：加算と乗算の組み合わせ

定数 10 と時刻を足し、さらに 2 倍にするグラフ：

```json
{
  "nodes": [
    {
      "id": "const10",
      "type": "constant",
      "params": {
        "value": 10
      }
    },
    {
      "id": "timer",
      "type": "clock"
    },
    {
      "id": "adder",
      "type": "add"
    },
    {
      "id": "doubler",
      "type": "multiply",
      "params": {
        "b": 2
      }
    }
  ],
  "edges": [
    {
      "from": "const10.out",
      "to": "adder.a"
    },
    {
      "from": "timer.t",
      "to": "adder.b"
    },
    {
      "from": "adder.out",
      "to": "doubler.a"
    }
  ]
}
```

このグラフの最終結果は、`engine.getValue("doubler.out")` で取得できます。

## 7. 公開 API

Loom の核となる API は `evaluateAt(time)` です。これは「ある時刻 `time` における全ノードの値を計算する純粋関数」として位置付けられます。`start()` / `stop()` はブラウザのアニメーションループ用の便利なラッパーであり、内部では `evaluateAt` を繰り返し呼び出しているだけです。

この設計により、Loom は以下の性質を持ちます：

- 同じグラフ・同じ時刻なら、常に同じ結果が得られる（決定的）
- リアルタイム実行に依存せず、テスト・録画・再生・サーバ側評価が可能
- ブラウザ環境を持たない Node.js などへの移植が容易（第一段階以降）

### Loom クラス

#### コンストラクタ：`new Loom(graph)`

```javascript
const engine = new Loom(graph);
```

**引数：**
- `graph`（オブジェクト）：グラフ定義（`nodes` と `edges` を持つオブジェクト）

**説明：**

グラフ定義を受け取り、エンジンを初期化します。この時点では評価ループは開始されていません。

グラフにサイクル（循環参照）が存在する場合、このコンストラクタはエラーを投げます。

**例：**
```javascript
const graph = { nodes: [...], edges: [...] };
const engine = new Loom(graph);
```

#### `engine.evaluateAt(time)`

```javascript
engine.evaluateAt(1.5);
const value = engine.getValue("wave.out");
```

**引数：**
- `time`（number）：評価する時刻（秒、エンジン起動時を 0 とする任意の double 値）

**説明：**

指定した時刻における全ノードの値を計算します。`getValue()` で取得できる値は、この呼び出しで更新されます。

これは Loom の核となる純粋関数的な評価メソッドです。同じグラフに対して同じ `time` を渡せば、常に同じ結果が得られます。

時刻は単調増加である必要はなく、過去の時刻を渡すことも、同じ時刻を複数回渡すことも可能です（第ゼロ段階では状態を持たないため、時刻の順序に依存しません）。

`engine.load(graph)` でグラフ更新が pending になっている場合、新グラフへの差し替えはこのメソッドの**開始時**に行われます。

**例：**
```javascript
// 任意の時刻を指定して評価
engine.evaluateAt(0);
console.log(engine.getValue("wave.out"));   // time=0 の値

engine.evaluateAt(1.5);
console.log(engine.getValue("wave.out"));   // time=1.5 の値

// 同じ時刻で再評価しても同じ結果
engine.evaluateAt(1.5);
console.log(engine.getValue("wave.out"));   // 上と同じ値
```

#### `engine.getValue(ref)`

```javascript
const value = engine.getValue("nodeId.portName");
```

**引数：**
- `ref`（文字列）：`"nodeId.portName"` 形式で、ノードの出力ポートを指定

**戻り値：**
- 現在のノード出力値（型は出力ポートに依存、通常は `number`）

**説明：**

グラフ上の任意のノードの現在の出力値を取得します。

指定されたノードやポートが存在しない場合、またはまだ評価されていない場合の動作は未定義です。

**補足：** 出力ポート名はノード型によって異なります。`clock` の出力ポートは `t`、それ以外のノード（`constant`、`sine`、`add`、`multiply`）の出力ポートは `out` です。

**例：**
```javascript
const current_time = engine.getValue("timer.t");
const wave_value = engine.getValue("wave.out");
```

#### `engine.load(graph)`

```javascript
engine.load(graph);
```

**引数：**
- `graph`（オブジェクト）：新しいグラフ定義

**説明：**

グラフを差し替えます。動作の詳細：

1. このメソッドの呼び出し時点で、新しいグラフを **検証**（重複 ID、未知の型、サイクルなどをチェック）
2. 検証に失敗した場合、エラーを投げる（既存のグラフは変更されない）
3. 検証に成功した場合、新しいグラフは **pending** として保存される
4. 次回の `evaluateAt()` 呼び出しの **開始時**に、pending のグラフが現行グラフと差し替えられる

つまり、`load()` の直後・`evaluateAt()` の前に呼び出した `getValue()` は、まだ **旧グラフ** に基づく値を返します。新グラフの値が見えるのは、次の `evaluateAt()` 以降です。

これにより、評価の途中でグラフ構造が変わることが防がれ、評価の整合性が保たれます。

**例：**
```javascript
const newGraph = { nodes: [...], edges: [...] };
engine.load(newGraph);  // この時点では pending

console.log(engine.getValue("oldNode.out"));  // 旧グラフの値

engine.evaluateAt(2.0);  // ここで新グラフに切り替わる

console.log(engine.getValue("newNode.out")); // 新グラフの値
```

#### `engine.start()`

```javascript
engine.start();
```

**説明：**

リアルタイム評価ループを開始します。これは便利機能であり、内部では `requestAnimationFrame` を使い、毎フレーム `evaluateAt(t)` を呼び出しているだけです（`t` はエンジン起動からの経過秒）。

リアルタイム実行を必要としない場合（テスト、サーバサイド、手動制御）は、`evaluateAt()` を直接呼び出すことを推奨します。

呼び出し後、`engine.stop()` が呼ばれるまで評価が続きます。

**例：**
```javascript
engine.start();
```

#### `engine.stop()`

```javascript
engine.stop();
```

**説明：**

`start()` で開始したリアルタイム評価ループを停止します。

呼び出し後も `getValue()` で最後の値を取得することはできます。手動で `evaluateAt()` を呼ぶこともできます。

**例：**
```javascript
engine.stop();
```

## 8. 評価モデル

### 初期化（グラフ読み込み時）

1. グラフの `nodes` 配列を検証（重複した ID がないか確認）
2. グラフの `edges` 配列を検証（存在しないノードやポートへのエッジがないか確認）
3. **トポロジカルソート** を実行し、ノード評価の順序を決定
4. サイクル（循環参照）が検出された場合、エラーを投げる

### 評価コンテキスト

毎フレーム、以下の情報をコンテキストとして保持します：

- `time`：エンジン起動からの経過秒数（秒単位、小数含む）

このコンテキストは、ノード評価時に参照されます（例：`clock` ノードが `time` を出力）。

### フレームごとの評価

毎フレーム、以下の処理が行われます：

1. `time` を更新（前フレームからの経過時間を加算）
2. ソース側からシンク側へ向けて、**トポロジカルソートされた順序** に従い、各ノードを順次評価
   - 各ノードは、入力ポートから値を読む
   - 入力エッジが接続されていないポート（未接続ポート）の値は `undefined` として扱われる
   - 各ノード型は、未接続ポートに対して適切なデフォルト値で処理する
   - 計算結果を出力ポートに書く
3. グラフの差し替え要求（`engine.load()` の呼び出し）があれば、新しいグラフに切り替え

### 未接続ポートの扱い

入力エッジが接続されていないポートの値は `undefined` として扱われます。各ノード型は、未接続ポートに対して以下のデフォルト値で処理します。

- `sine.t`：未接続時は `0` として扱う
- `add.a`：未接続時は `0` として扱う
- `add.b`：未接続時は `params.b`（デフォルト `0`）を使用
- `multiply.a`：未接続時は `1` として扱う
- `multiply.b`：未接続時は `params.b`（デフォルト `1`）を使用

これにより、エンジンは未接続ポートがあっても安全に評価を継続できます。

## 9. 配布形態

### ファイル形式

ES Module（ESM）形式の単一 JavaScript ファイルとして配布されます。

```html
<script type="module">
  import { Loom } from './src/loom.js';
  const engine = new Loom(graph);
  engine.start();
</script>
```

### ファイルパス

- `src/loom.js`

リポジトリのルートではなく、`src/` ディレクトリに配置されます。

### ビルドツール

ビルドツール（webpack、esbuild など）を使いません。人が読める単一ファイルのまま配布されます。

### 依存ライブラリ

ゼロです。Three.js や d3.js などの外部ライブラリに依存しません。

これにより、ファイルサイズが最小化され、読み込みが高速化されます。

## 10. エラー仕様

Loom が投げるエラーは、すべて **構造化エラーオブジェクト** として表現されます。これにより、エラーハンドリングが容易になり、将来的に AI が自動修正することも可能になります。

### エラーオブジェクトの構造

エラーは以下のフィールドを持つオブジェクトとして投げられます：

```javascript
{
  code: "ERROR_CODE",      // エラーの種別（文字列）
  message: "human-readable description",  // 人間向けメッセージ
  // 以下、エラー種別ごとの追加情報
}
```

JavaScript の `Error` オブジェクトを継承する形で実装されることを推奨します（`error.code`、`error.message` でアクセス可能）。

### 第ゼロ段階のエラー種別

#### `DUPLICATE_NODE_ID`

同じ `id` のノードがグラフ内に複数存在する場合に発生します。

**追加フィールド：**
- `nodeId`（文字列）：重複している ID

**例：**
```javascript
{
  code: "DUPLICATE_NODE_ID",
  message: "Node id 'timer' is duplicated",
  nodeId: "timer"
}
```

#### `UNKNOWN_NODE_TYPE`

`type` が未知の値である場合に発生します。

**追加フィールド：**
- `nodeId`（文字列）：問題のあるノードの ID
- `type`（文字列）：未知の型名

#### `UNKNOWN_NODE`

エッジが指す `nodeId` が、グラフ内のどのノードとも一致しない場合に発生します。

**追加フィールド：**
- `edge`（オブジェクト）：問題のあるエッジ
- `nodeId`（文字列）：見つからないノード ID

#### `UNKNOWN_PORT`

エッジが指すポート名が、ノード型の定義に存在しない場合に発生します。

**追加フィールド：**
- `edge`（オブジェクト）：問題のあるエッジ
- `nodeId`（文字列）：ノード ID
- `port`（文字列）：見つからないポート名

#### `DUPLICATE_INPUT_EDGE`

同じ入力ポートに複数のエッジが接続されている場合に発生します。

**追加フィールド：**
- `nodeId`（文字列）：受信側ノードの ID
- `port`（文字列）：受信側ポート名

#### `CYCLE`

グラフにサイクル（循環参照）が存在する場合に発生します。

**追加フィールド：**
- `cycle`（配列）：サイクルを構成するノード ID の配列

**注意：** 第ゼロ段階では、すべてのサイクルがエラーとなります。第二段階以降で状態ノード（`accum`、`smooth` など）を導入した際、状態ノードをまたぐサイクル（フィードバックループ）の許可を検討します。

#### `INVALID_GRAPH`

その他、グラフ定義が構造的に不正な場合に発生します（例：`nodes` フィールドが配列でない、`id` フィールドが欠けている、など）。

**追加フィールド：**
- `detail`（文字列）：不正の詳細

### エラーが発生するタイミング

エラーは以下のタイミングで発生する可能性があります：

- `new Loom(graph)`：コンストラクタによるグラフ検証時
- `engine.load(graph)`：新グラフの検証時

`evaluateAt()`、`getValue()`、`start()`、`stop()` は、グラフ自体に問題がない限りエラーを投げません。

## 11. ロードマップ

### 第一段階：ノード追加とイベント型の導入

- 数学系ノード（`subtract`、`divide`、`mod`、`abs`、`min`、`max`、`clamp`、`mapRange`、`lerp`）の追加
- 波形系ノード（`saw`、`triangle`、`square`、`noise`、`random`）の追加
- 入力ノード（`pointerPosition`、`pointerClick`、`viewportSize` など）の追加
- イベント型値の設計と実装
- イベント↔連続値の変換ノード（`hold`、`sample`、`threshold`、`changed` など）
- ノード型の型システム拡張（`vec2`、`vec3`、`color`、`boolean`、`string` など）

### 第二段階：状態部品の導入と同期ポリシー

- 状態を持つノード（`accum`、`smooth`、`delay`、`toggle` など）の実装
- 状態のシリアライズ・リセット機構（`reset()`、`serialize()`、`deserialize()`）
- 状態ノードを介したフィードバックループの許可検討
- 複数クライアント環境での状態同期ポリシー（スナップショット送信、権威ノードなど）の検討
- `strict` モードの導入（未接続必須ポートをエラーとする実行モード）

### 第三段階：デバッグとイントロスペクション

- `engine.inspect(ref)`：ノードの計算過程を取得する API
- `engine.snapshot()`：全ノードの現在値を一括取得
- `engine.watch(ref, callback)`：値の変化を監視する API
- 構造化エラーの拡張（`suggestions` フィールドなど）
- 時間スライダーによる時間旅行デバッグ UI の試作

### 第四段階：テキスト記法（DSL）とパッチ操作

- 専用 DSL（テキスト記法）の設計とパーサ実装
- DSL ↔ JSON の相互変換ツール
- グラフ差分・パッチ形式（`addNode`、`removeNode`、`setParam` など）の設計
- AI 連携用ツール定義（関数呼び出し API への統合）

### 第五段階：ビジュアルエディタとプリセット

- ブラウザベースのビジュアルノードエディタ
- ノード現在値のグラフ上表示
- サブグラフ（複数ノードを部品化する仕組み）
- プリセット集（モーション、カラー、インタラクション）

### 第六段階：マルチクライアント同期と各種アダプタ

- 複数クライアントでのグラフ・状態の同期機能
- イベント配信ノードによる broadcast
- 3D エンジン連携アダプタ（Three.js など）
- 録画・再生・タイムトラベル機能
